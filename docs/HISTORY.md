## 4-0. EIASS 접속 — 서울 중계로 풀었다 (2026-08-09) ★ 최신

**§4 아래에 적힌 "GitHub 러너로는 불가" 는 사실이지만, 우회로를 찾았다.**

### 원인이 **두 가지**였다

| | 무엇 | 어떻게 드러났나 |
|---|---|---|
| ① | 나가는 IP (미국 Azure) | 서울에서는 붙고 미국에서는 안 붙는다 |
| ② | **EIASS 가 중간 인증서를 안 보낸다** | 서울에서도 **450ms 만에 붙었다가** `UnknownIssuer` 로 끊겼다 |

**②를 여태 아무도 몰랐던 이유**: 브라우저와 파이썬(`requests`)은 빠진 중간 인증서를
알아서 보충한다. Deno 는 안 한다. 그래서 서울로 옮기고 나서야 드러났다.

- EIASS 인증서 발급자는 **Sectigo**(흔한 상용 CA). 뿌리 인증서는 어디에나 있다.
- `openssl s_client` 로 보면 **인증서가 1장만** 온다 = 체인이 불완전하다.
- 중계에 그 중간 인증서 한 장을 넣어 해결했다. **검증을 끈 것이 아니라 정상 검증되게 한 것이다.**

### 실측 (2026-08-09)

| 시험 | 결과 |
|---|---|
| 서울에서 실행 | 13/13 (`x-sb-edge-region: ap-northeast-2`) |
| EIASS 접속 | **13/13** (GitHub 직접은 6번 중 1번) |
| 목록 조회 | 5/5 · 평균 121ms |
| 7.4MB PDF | 5/5 · 전부 **7,743,774 바이트** (한국 PC 에서 받은 것과 동일) |
| 대조군(인증서 없이) | 전부 실패 → 원인 확정 |

**대조군을 같이 돌린 것이 중요했다.** 실험군만 성공한 게 아니라
**대조군이 매번 실패**했기 때문에 "인증서가 원인"이라고 말할 수 있다.

### 만들면서 겪은 것 세 가지

1. **측정 스크립트가 거짓말을 했다.** 셸에 한글 키를 박은 파이썬을 넣었더니 인코딩이
   깨져 **8번 성공한 것이 8번 실패로 찍혔다.** 판정을 뒤집을 뻔했다.
   → 측정 코드는 **파일로 빼서** 돌린다. 셸 한 줄짜리로 판정하지 않는다.
2. **HTTP 헤더에 한글을 넣으면 안 된다.** 중계가 오류 까닭을 한글로 헤더에 담고 있었다.
   헤더 값은 라틴 문자만 되므로 **오류를 알리려다 그 자리에서 또 죽는다.**
   → 까닭은 **본문**에, 헤더에는 **짧은 아스키 코드**만. (가짜 중계로 미리 시험하다 잡았다)
3. **heredoc 이 백슬래시와 `\r` 을 먹었다.** `collect.yml` 에 `tr -d '\r'` 을 넣었더니
   **실제 CR 바이트**가 파일에 박혀 YAML 이 깨졌다.
   → 셸 heredoc 으로 코드 파일을 쓰지 않는다. 편집 도구나 파이썬으로 쓴다.

### 구조

```
[GitHub Actions · 미국]                    [Supabase · 서울]          [EIASS]
  build_data.py (파이썬 그대로)
    │  requests 가 주소별로 통로를 나눈다
    ├─ EIASS 주소  → _RelayAdapter ──────▶ eiass-relay ──────────▶ ✅
    │                (x-region: 서울)        (중간 인증서 보충)
    └─ VWorld/Anthropic → 그대로 직접 ─────────────────────────────▶ ✅
```

- **부르는 코드는 한 줄도 안 바뀌었다.** `requests` 의 주소별 통로(mount) 를 이용했다.
- **환경변수 두 개가 없으면 아무 일도 안 일어난다** — 예전처럼 직접 접속한다.
  한국 PC(`run_daily.bat`)는 직접 가는 게 빠르므로 안 쓴다.
- 무료 한도: 월 5GB 전송 / 50만 회 호출. 실제 사용은 **월 450MB 안팎**(10%).
  단 `--full` 은 한 번에 150MB 이상이라 **한국 PC 에서 돌리는 게 낫다.**

### ★ GitHub 러너에서 실제로 확인 (2026-08-12)

`check.yml` 을 실제 러너에서 돌려 **같은 서버·같은 순간에** 두 길을 비교했다.
이보다 깨끗한 대조는 나오기 어렵다.

| | 결과 |
|---|---|
| 러너 위치 | `52.173.13.232` — **US / Des Moines, Microsoft Azure** |
| **직접 연결** | **실패 — 20초 타임아웃** (문서에 적힌 실패 양상 그대로 재현) |
| **서울 중계** | **성공 — 지역 `ap-northeast-2`, 목록 10,428 bytes, 1.5초** |

→ "GitHub 러너에서는 안 된다"도 사실이고, "중계를 거치면 된다"도 사실임을
**한 번의 실행 안에서** 확인했다.

**함께 나온 것 — VWorld 루트가 502 였다.**
같은 시각 한국에서는 200 이었고, 8/6 기록으로는 같은 러너에서 0.43초에 붙었다.
**한 번 본 것으로 단정하지 않는다.** 대신 점검을 고쳤다 —
루트 대신 **실제로 쓰는 지오코더 경로**를 부르고, 아예 안 닿을 때만 오류로 친다.
(좌표를 못 얻은 사업은 다음 수집 때 다시 시도하므로 치명적이지 않다)

### 남은 위험

**EIASS 인증서는 2027-03-29 에 만료된다.** 갱신 때 인증기관이 바뀌면 중계가 멈춘다.
새 중간 인증서를 받는 방법은 `tools/relay/index.ts` 맨 위 주석에 적어 두었고,
중계가 인증서 문제로 실패하면 그렇다고 말해 주도록 만들었다.

## 4. 중요한 결정과 이유 (되돌리지 말 것)

세부 규칙은 전부 `CLAUDE.md`에 있다. 여기는 **왜 그렇게 결정했는지**만 요약.

### 기준은 "공람 종료일"이 아니라 "의견제출 마감일" (2026-08-03 변경)
환경영향평가법 시행령 제38조: 공람이 끝난 뒤 7일 이내까지 의견을 낼 수 있다.
공람 종료일로 끊으면 아직 의견을 낼 수 있는 사업이 화면에서 사라진다.

### 단, 환경영향분석(AI 해석)만은 "공람 기간"에만 보여준다 ★ 헷갈리기 쉬움
평가서 초안 자체가 법적으로 공람 기간에만 열람 가능하다. 의견은 그 뒤에도 낼 수 있지만,
**해석은 공람 기간이 끝나면 바로 닫는다.** `viewOpen`(공람 중)과 `open`(의견 가능)을
코드에서 분리해 두었다 — 절대 하나로 합치지 말 것. `CLAUDE.md` "기간 규칙" §4 참고.

### AI는 번역만 한다
항목을 8개로 고정, 없으면 `null` + "관련 내용이 없습니다". 판단·홍보 문구 금지.

### 도면(그림)을 읽어 노선을 뽑지 않는다
좌표 격자가 없어 픽셀→위경도 변환 기준점이 없다. 대신 하천 이름으로 VWorld 하천망도에서
실제 도형을 받는다. 하천 사업에만 적용(도로 요약문의 "지나가는 하천" 이름과 구분).

### 선형 사업은 주소 한 점이 아니라 노선까지의 최단거리로 반경을 판단한다 (8/3 추가)
대표 주소가 노선에서 멀리 떨어진 경우가 흔하다(파주 주소, 계양구 코앞 노선 등).
노선 도형이 있는 사업만 해당(도로·철도는 여전히 주소 한 점).

### ~~휴대폰용 사이트를 따로 만들지 않는다~~ → **뒤집었다 (2026-08-06)**
원래는 "같은 화면이 폭에 따라 바뀐다"였다. 그런데 폭 기준으로 데스크톱을 줄여 쓰는 방식이
휴대폰에서 계속 깨졌다(가로 목록 0px, 세로 37px). 그래서 **화면(HTML·CSS)만 나눴다** —
`index.html` / `m.html`. **두뇌(`app.js`)와 긴 안내문(`texts.js`)은 여전히 하나다.**
갈라지면 안 되는 것은 §7 3차 기록에 적어 두었다.

### EIASS 접속 — "해외 IP 차단"은 틀렸고, 그렇다고 GitHub에서 되지도 않는다 (2026-08-06) ★★

**이 항목은 원래 "수집은 한국에서만 돌린다 / EIASS가 해외 IP를 막는다"였다. 사실이 아니었다.**
같은 실수를 반복하지 않도록 어떻게 틀렸는지까지 남긴다.

**무엇이 틀렸나**
- 근거가 **2026-08-01에 딱 한 번 돌려 실패한 것** 하나뿐이었다. 재시도가 없었다.
- 원인을 밝히려고 `collect.yml`에 넣어 둔 '연결 확인' 단계는 **그 실패 뒤에 추가됐고,
  오늘까지 한 번도 실행된 적이 없었다.** 진단 도구를 만들어 놓고 써 보지 않았다.
- 그런데 결론은 `CLAUDE.md`·`HANDOFF.md`·`collect.yml` 세 곳에 "확인함"으로 박혔고,
  "다시 시도하지 말 것" 목록에까지 올라갔다. 그 뒤로 아무도 의심하지 않았다.
- 그 틀린 전제 위에서 **AWS Lightsail 이전(월 7천원 + 서버 관리)** 을 검토했다.

**실제로 확인한 것 (2026-08-05~06)**
- 전 세계 20개 노드 중 17곳 정상 — 미국 LA **0.49초**, 댈러스 1.09초, 독일·프랑스·네덜란드·러시아·인도·베트남
- GitHub 러너(미국 Azure)에서도 EIASS **0.23초**, VWorld 0.22초 정상
- `www.eiass.go.kr`은 AAAA(IPv6) 레코드가 없다 → IPv6 문제도 아니었다
- 다만 **간헐적으로 접속이 안 되는 것은 사실**이다. GitHub에서 3번 시험해 1번 성공:

  | 회차 | 러너 IP | 결과 |
  |---|---|---|
  | 1차 | `52.159.244.171` (San Jose) | DNS 조회 실패 (10초) |
  | 2차 | `9.234.149.180` (Boydton) | DNS는 됐는데 TCP 443 무응답 (20초) |
  | 3차 | `20.161.78.74` (Boydton) | 전부 정상 (0.23초) |

  **2·3차는 같은 데이터센터인데 결과가 달랐다.** 차단이라면 세 번 다 같은 지점에서 막혔어야 하고,
  실패 지점이 DNS·TCP로 제각각일 이유도 없다. 이건 차단이 아니라 불안정이다.

**그래서 어떻게 했나 — 그리고 그래도 안 됐다 (같은 날 오후 추가 기록)**

재시도 통로(`SESSION`, 4·8·16초 쉬며 4번)를 넣고, `collect.yml`에 1분 쉬고 통째로 한 번 더
시도하는 장치까지 넣은 뒤 실제로 3번 돌렸다. **3번 다 실패했다.**

| 실행 | 소요 | 실패 지점 |
|---|---|---|
| 00:38 | 100초 | 목록 받기 — 재시도 4번 소진 후 죽음(예외 처리가 없어 통째로 중단) |
| 00:50 | 148초 | 같음. 연결 확인 단계도 19초 걸림(둘 다 무응답) |
| 00:59 | 410초 | 2번 시도 모두 `ConnectTimeout`. **연결 확인: EIASS 실패(14.7초) / VWorld 성공(0.43초)** |

**마지막 줄이 결정적이다.** 같은 러너·같은 순간에 **VWorld는 0.43초에 붙는데 EIASS만 시간 초과**했다.
- "해외 IP 차단"이 아니다 → 전 세계 17곳에서 정상 접속된다.
- "Azure↔한국 경로 문제"도 아니다 → 같은 러너에서 VWorld(한국)는 멀쩡하다.
- 남은 설명은 **EIASS 쪽에서 특정 IP·대역을 불안정하게 거부한다**는 것뿐이다.

**최종 집계: GitHub 러너에서 EIASS 접속 6번 시도 → 1번 성공(약 17%).**
반면 **한국 PC에서는 매번 0.08초, 실패 0회.**

→ 결론: **GitHub 무료 러너로 수집하는 것은 사실상 불가.** 수집 위치를 정하는 것이 §2의 1순위다.

**교훈 두 가지**
1. **한 번 실패한 것을 "확인함"이라고 쓰지 말 것.** 특히 그 결론이 돈 쓰는 결정으로 이어질 때는.
2. **반대로, 몇 번 성공한 것을 "된다"고 단정하지도 말 것.** 3번 중 1번 성공을 보고
   "재시도로 덮을 수 있다"고 판단해 자동화를 켰지만, 실제로는 덮이지 않았다.
   접속이 안 될 때는 **몇 분 동안 계속** 안 되는 양상이라 재시도가 무력하다.

**WARP 우회를 넣어 봤고 — 실패로 끝났다 (2026-08-07~08 확인) ★**

원인이 "EIASS 쪽이 Azure 대역을 거르는 것"으로 좁혀졌으므로, 남은 수단은
**나가는 IP 를 바꾸는 것**뿐이었다. 근거: Cloudflare 서버(미국)에서는 EIASS 가
정상 응답했다(r.jina.ai 실측). 그래서 `collect.yml` 이 수집 전에
**EIASS 행 트래픽만**(해당 IP /32) Cloudflare WARP 터널(무료·계정 불요, `wgcf`)로
라우팅하게 해 뒀다. 순서: WARP(2408) → WARP(500) → 직접 → 실패 시 안전 중단.

**결과: 자동 수집 3회 모두 같은 지점에서 실패했다.**

| 실행 | 실패한 단계 | 주석에 남은 판정 |
|---|---|---|
| 8/07 08:20 | `EIASS 가는 길 확보` | `[통로] WARP·직접 모두 실패 … / VWorld FAIL` |
| 8/07 23:48 | 같음 | 같음 |
| 8/08 06:08 | 같음 | 같음 |

- **`VWorld FAIL` 이 같이 찍힌 것이 눈에 띈다.** 8/6에는 같은 러너에서 VWorld 가
  0.43초에 붙었는데 이번엔 VWorld 까지 실패다. **WARP 설치가 러너 네트워크를
  망가뜨렸을 가능성**이 있다(확인 안 됨). 다시 손댈 거라면 이것부터 볼 것.
- 실패는 **무해하다** — 커밋 전에 멈추므로 자료가 안 망가지고 비용도 0원이다.
- **→ 선택지 D는 탈락. GitHub 러너 쪽 길은 이제 다 막혔다.** 남은 건 A/B/C 중 사람이 고르는 일.

### ✅ 최근에 끝낸 것 ⓪-5 — 위성지도 추가 (2026-08-16)

**기본은 일반지도, 단추 하나로 위성 전환.** 지도 화면(두 화면 모두) + 노선 그리기 도구.

- 위성은 지명이 없어 **`Satellite` + `Hybrid`(지명·도로) 두 장 세트**로 올린다.
  실측 무게: 일반 4~38KB / 위성 13~41KB + Hybrid 42~83KB → **3배 넘게 무겁다.** 그래서 기본이 아니다
- `Satellite` 만 **확장자가 `jpeg`** 다. `gray` 는 이 키로 안 되고, `midnight` 은 이 서비스엔 안 맞는다
- 고른 값은 `wdn.maplayer` 에 남고 **노선 도구와 공유**한다
- **미니 지도에는 안 넣었다** — 작아서 마커·경계가 묻힌다

**★ 색 잡는 데서 한 번 크게 헛짚었다. 이 실패를 꼭 남겨 둔다.**

타일만 바꿨더니 "마커·노선이 안 보인다"는 지적을 받았다. 그래서 **위성 배경 밝기를 실측**하고
(산·논밭·도시·물 5곳 — 중앙 0.069 · 하위5% 0.021 · 상위5% 0.196)
대비비가 높은 색으로 바꿨다. 수치는 1.10 → 9.23 으로 좋아졌는데
**화면은 더 나빠졌다.** 파스텔이라 **위성 사진의 안개·구름처럼 보였다.**

> **무엇이 잘못이었나 — 글자용 잣대를 마커에 갖다 썼다.**
> WCAG 명도 대비는 '배경과 밝기가 얼마나 다른가'만 본다. 그래서 계속 옅은 쪽으로 밀린다.

① 진한 색(파스텔 금지) ② 흰 테두리 2~3px ③ 그림자로 띄우기
④ 위성이라고 마커 색을 바꾸지 않기 ⑤ 노선은 짙은 테두리 + 채도 높은 선

| 요소 | 일반 | 위성 |

| 전략 마커 | `--p80` | **`--accent`**(선명한 파랑) — 짙은 남색만은 어두운 산 위에서 원리적으로 안 된다 |

### ✅ 최근에 끝낸 것 ⓪-10 — 휴대폰 쓰임새 손보기 (2026-08-16, 실사용 지적)

폰으로 직접 써 보고 나온 네 가지를 고쳤다. **셋은 "있는 줄도 몰랐다"는 종류였다.**

**① 아래 탭 막대가 안 보였다**
흰 배경 + 옅은 회색 글자(`--ink-4`) + 1px 선이라 본문과 안 갈렸다.
**하나만 고쳐서는 안 되고 셋을 함께** 고쳐야 했다:
위쪽 **그림자**(선 1px 로는 부족) · 글자 `--ink-4`→`--ink-2`(**대비 2.6 → 9.3**) ·
고른 탭 아이콘 뒤 **알약 배경**(색 말고 모양으로도 알 수 있게).

**② 탭 구성: '안내'를 빼고 '관심목록'을 넣었다**
안내는 자주 볼 것이 아니라 머리말·푸터로 충분하다. 담아 둔 사업은 마감을 지켜보려고
담은 것이라 **자주 들어와야 하는 자리**다. 탭은 5개를 유지했다(애플 권장).

**③ 지도에서 목록·상세를 열면 돌아가기가 어려웠다**
손잡이는 '한 단계씩 도는' 물건이라 **'작게'에서 지도를 보려면 세 번**을 눌러야 했고,
상세를 열면 나갈 길이 그것뿐이었다. 손잡이 줄 오른쪽에 **`지도 보기` 단추**를 뒀다.

| 단계 | 결과 |
|---|---|
| 들어오면 | `sheet-closed` · 단추 숨김(뜻이 없으므로) |
| 목록 보기 | `sheet-peek` · 단추 보임 |
| 상세 열기 | `sheet-full + on-detail` |
| **`지도 보기` 한 번** | `sheet-closed` · **상세도 같이 닫힘** · 지도 760px 복귀 |

**④ 지도는 언제나 일반지도로 시작한다**
고른 값을 기억하지 않는다. 예전에 위성으로 저장해 둔 브라우저도 이제 일반지도로 열린다(실측).
위성은 지명 글자가 없어 첫 화면으로 맞지 않다. `route_editor.html` 은 예외로 기억한다.

**⑤ 휴대폰의 캘린더 구독 칸을 관심목록 화면으로 옮겼다**
사업 목록 아래에 두었더니 스크롤 끝까지 내려야 나와서 아무도 못 봤다.
캘린더 이야기(마감일 넣기 + 지역 구독)를 한자리에 모았다. **데스크톱은 그대로**다.
