### 배포 후 실제 확인 (2026-08-01 저녁)

**사이트가 살아 있다: https://dongdong1226.github.io/alrimi/**
사업 36건 로드 · 배포 키 인식 · 표본 안내 띠 없음 · 지도 타일 16개 정상 로드.

**겪은 문제 — GitHub Secret 의 VWorld 키 앞에 공백 한 칸이 딸려 들어갔다.**

```
INVALID_KEY — 등록되지 않은 인증키입니다.
```

증상이 아주 헷갈렸다. **지도 타일(WMTS)은 정상으로 나오는데 지오코더만 거부**된다.
WMTS 는 URL 경로에 키가 들어가서 공백을 무시하고, 지오코더는 질의 파라미터라 그대로 걸린다.
처음엔 활용API 에서 `지오코더 API` 를 빠뜨린 줄 알았는데, 키 설정은 멀쩡했다.

**찾은 방법**: 배포된 페이지에서 키 길이를 세어 봤더니 36자가 아니라 **37자**였다.
같은 키를 `trim()` 해서 지오코더를 부르니 바로 `OK` 가 나왔다.

영향: 주소→좌표 변환이 실패해 **관리자 기본 좌표(37.5636, 127.1946)로 되돌아갔고**,
반경 3km 안 사업이 0건으로 나왔다.

**고침 (코드 3곳에서 공백을 걷어낸다)**:

| 곳 | 무엇 |
|---|---|
| `deploy.yml` | Secret 값을 `.strip()` 한 뒤 `config.js` 에 심는다. 공백이 있었으면 경고를 남긴다 |
| `assets/app.js` | 배포 키·저장된 키 둘 다 `trim()` |
| `tools/build_data.py` | `VWORLD_KEY` · `VWORLD_DOMAIN` · `ANTHROPIC_API_KEY` 전부 `.strip()` |

관리자 화면 입력은 원래 `.trim()` 하고 있었다.

> **교훈**: API 키가 거부되면 값이 틀렸는지 보기 전에 **길이부터 세어 본다.**
> 붙여넣기 공백은 흔하고, 증상이 엉뚱한 곳에서 나타난다.

### 배치 파일 줄바꿈 함정 (CRLF)

`tools/run_daily.bat` 을 LF 로 저장했더니 **더블클릭해도 아무 일도 안 일어났다**
(cmd 가 파일을 읽다 말고 조용히 끝난다. 로그에 첫 줄도 안 찍힌다).
CRLF 로 다시 저장해 해결했고, `.gitattributes` 에 `*.bat text eol=crlf` 를 넣어 고정했다.
창이 바로 닫히지 않도록 끝에 `timeout /t 30` 도 넣었다(작업 스케줄러에서는 그냥 지나간다).

## 3. 중요한 결정과 이유 (되돌리지 말 것)

CLAUDE.md에 규칙으로 적혀 있지만, **왜 그렇게 정했는지**를 남긴다.

### 공람 기간이 지난 사업은 AI 해석을 보여주지 않는다
의견을 낼 수 없는 시점에 해석만 남아 잘못 참고되는 것을 막기 위함.
파일을 만든 날과 보는 날이 다를 수 있어서 **화면에서 매번 날짜를 다시 판단**한다.

### AI는 번역만 한다
항목을 8개로 고정하고, 요약문에 없으면 `null`로 두고 "관련 내용이 없습니다"로 표시.
`app.js`의 `EIA_FIELDS`와 `build_data.py`의 `EIA_FIELDS` **키가 반드시 같아야 한다.**

### 도면(그림)을 읽어 노선을 뽑는 방식은 쓰지 않는다
평가서 도면에 노선은 빨간 선으로 있지만 **좌표 격자가 없어 픽셀→위경도 기준점이 없다.**
(요약문 PDF에는 도면조차 없고, 다른 첨부의 경위도 표는 노선이 아니라 행정구역의 동서남북 끝 좌표다.)
틀린 노선은 없는 노선보다 나쁘다 — "우리 집 앞을 지나가나?"에 잘못 답하면 안 되니까.

**대신**: 요약문 글자에서 하천 이름을 찾아 VWorld 하천망도(`LT_C_WKMSTRM`)에서 실제 도형을 받는다.

### 하천 사업에만 하천 노선을 붙인다
도로 사업 요약문에도 "지나가는 하천" 이름이 나온다. 그걸 노선으로 그리면 틀린 그림이 된다.
`사업구분`·`근거법령`에 "하천"이 있을 때만 적용 (`is_river_project()`).
도로·철도 선형 사업은 **관리자가 직접 그린다.**

### 환경영향평가의 위치 유형은 추측하지 않는다
전략환경영향평가는 면형/선형 표시가 있는데 환경영향평가는 **아예 없다**(확인함).
없으면 `locationTypes: []`로 두고 태그를 안 붙인다.

### 없는 값은 만들지 않는다
주민 의견 수, 설명회 참가 현황은 EIASS에서 수집되지 않는다 → 0 또는 "아직 수집하지 않음".
설명회 일시는 사업마다 자유 형식(`260814 오전 10시` / `2026.08.06(목) 14:00`)이라 **원문 그대로** 보여준다.

## 4-1. GitHub Actions 자동화 — 켜는 순서

> **처음 켜는 사람은 `docs/SETUP.md`를 본다.** 클릭 하나하나까지 적어 둔 설명서다.
> 아래는 요약이다.

**아직 안 켰다.** 파일은 다 만들어 뒀고, 아래 4단계를 사람이 해야 켜진다.

> GitHub Actions는 **서버가 아니다.** 정해진 시각에 스크립트를 한 번 돌리고 끝나는
> 작업 실행기다. 결과 파일을 저장소에 커밋하면 GitHub Pages가 그걸 방문자에게 전달한다.
> 항상 떠 있는 서버는 없고, 이 서비스에는 필요하지도 않다.

### 1) VWorld 키를 배포 주소로 새로 발급
vworld.kr 신청서의 **`서비스URL` 칸이 곧 도메인 제한이다** (별도 항목은 없다).
거기에 `https://dongdong1226.github.io/alrimi/` 를 넣는다.

**지금 `.env`의 키는 `http://localhost:8000` 으로 등록돼 있어 배포 사이트에서 안 먹는다.**
그래서 새 키가 필요하다 — 보안 때문이 아니라 안 그러면 지도가 안 뜨기 때문이다.
기존 localhost 키는 `.env`에 그대로 두고 내 컴퓨터용으로 계속 쓴다 (키 2개 운영).

활용API는 **2D 지도 / WMTS·TMS / 2D데이터 / 지오코더** 네 개를 고른다.

### 2) 저장소 Secrets 등록
`Settings → Secrets and variables → Actions → New repository secret`

| 이름 | 값 |
|---|---|
| `VWORLD_KEY` | 1)에서 새로 받은 키 |
| `ANTHROPIC_API_KEY` | `.env`에 있는 것과 같은 키 |

같은 화면 **Variables** 탭에 `VWORLD_DOMAIN` = `https://dongdong1226.github.io/alrimi/` 도 넣는다.
**1)의 서비스URL과 글자 하나까지 같아야 한다** (다르면 하천 조회가 `INCORRECT_KEY`).

> **ANTHROPIC_API_KEY는 브라우저로 절대 가지 않는다.** 파이썬이 GitHub 서버 안에서만 쓴다.

### 3) Pages 설정
`Settings → Pages → Source` 를 **"GitHub Actions"** 로 바꾼다.
(브랜치 배포가 아니라 Actions가 만든 결과물을 올리는 방식. 그래야 VWorld 키를
git에 커밋하지 않고 배포할 때만 심을 수 있다.)

### ⚠️ 4)는 실패로 끝났다 — 결론이 나왔다

**EIASS가 GitHub 서버(미국)를 막는다.** 2026-08-01 확인:

```
requests.exceptions.ConnectTimeout
  Connection to www.eiass.go.kr timed out. (connect timeout=20)
```

DNS는 풀리는데 TCP 연결이 무응답 = 거부(403)가 아니라 차단. 우회 불가.

**확정된 방식:** 수집은 내 PC(`tools/run_daily.bat` + 작업 스케줄러),
배포는 GitHub Actions(`deploy.yml`, 푸시하면 자동). 배포는 이미 성공을 확인했다.
`collect.yml`은 지우지 않고 **자동 실행만 껐다**(매일 실패 알림이 오면 안 되므로).

아래 4)~5)는 나중에 차단이 풀렸을 때를 위해 남겨 둔다.

### 4) 손으로 한 번 돌려서 확인 — (지금은 실패한다)
`Actions → EIASS 공람 자료 수집 → Run workflow` 에서 **limit을 3으로** 넣고 실행한다.

**확인할 것: EIASS가 GitHub의 해외 IP를 막지 않는지.**
한국 정부 사이트는 해외 IP를 차단하는 경우가 있다. 내 PC(한국)에서는 되지만
GitHub 서버(미국)에서는 안 될 수 있다. **이건 아직 확인 못 했고, 막히면 이 계획 전체가 무산된다.**
로그에 `[전략환경영향평가] 1페이지 ...` 가 찍히면 통과. 타임아웃이나 403이 나면 막힌 것이다.

막혔을 때 대안: 지금처럼 `tools/run_daily.bat` + 윈도우 작업 스케줄러로 내 PC에서 돌리고,
결과만 커밋한다 (컴퓨터가 켜져 있어야 한다는 제약은 남는다).

### 만들어 둔 파일
| 파일 | 역할 |
|---|---|
| `.github/workflows/collect.yml` | 매일 00:00 UTC(한국 09:00) 수집 → `projects.json` 커밋 → 배포 호출 |
| `.github/workflows/deploy.yml` | 사이트 배포. **올리기 직전에만** Secret에서 VWorld 키를 `assets/config.js`에 심는다 |
| `assets/config.js` | 빈 채로 커밋돼 있다. 배포 때 덮어써진다. 내 PC에서는 비어 있어 관리자 화면 입력을 쓴다 |
| `requirements.txt` | 파이썬 패키지 목록 |

키 우선순위 (검증함): **관리자 화면 입력 > 배포에 심은 키 > 없음(안내 문구)**

## 6. 알려진 함정

- **VWorld 데이터 API는 `domain` 파라미터가 없으면 `INCORRECT_KEY`가 난다.**
  발급 때 등록한 서비스 URL과 같아야 한다 (`.env`의 `VWORLD_DOMAIN`, 기본 `http://localhost:8000`).
- **화면을 `file://`로 열면 json을 못 읽어** 표본 데이터로 대체된다. 반드시 로컬 서버로 열 것.
- EIASS 사이트는 `frameset` 구조라 겉 URL로는 내용을 못 본다. 엔드포인트를 직접 호출한다
  (구체적인 URL·파라미터는 CLAUDE.md의 "데이터 파이프라인" 표에 있음).
- EIASS 상세페이지는 **POST로만 열린다.** 링크가 아니라 숨은 폼을 만들어 제출한다.
- 파이썬 로그에 표시 못 하는 문자가 섞이면 윈도우 cp949 콘솔에서 죽는다 → `log()`가 처리 중.
- `data/regions.json`의 시도가 **16개**다(17개가 아님). VWorld 자료가 최신이라
  광주광역시+전라남도가 "전남광주통합특별시"로 통합돼 있다.
