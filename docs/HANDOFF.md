## 0. 한 문단 요약 — 지금 어디까지 왔나

**만들려던 기능은 다 만들었고, 수집·배포가 자동으로 돈다.** 전국 공람 관련 사업 **41건**을 수집해

데이터로 동작한다. 가장 중요한 규칙은 **"공람 종료일"이 아니라 "의견제출 마감일" 기준으로
사업을 보여주는 것**이다 (단, AI 해석만은 법적으로 공람 기간에만 보여준다 — 절대 헷갈리면
안 되는 부분).

**8/6~8/8 사흘간 화면을 크게 손봤다.** 굵직한 것만:

- **휴대폰 화면을 따로 분리했다** — `m.html` + `mobile.css` + `mobile.js`.
  원래 "따로 만들지 않는다"가 결정이었는데, 폭 기준으로 데스크톱을 줄여 쓰는 방식이
  계속 깨져서(가로 화면 목록 0px, 세로 37px) **뒤집었다.**
  단 판단 로직(`app.js`)과 법 조문 안내문(`texts.js`)은 **하나로 공유**한다.
- **동네를 세 칸 다 안 골라도 되게** 했고(`전국`·`전체` 추가), **`지금 내 위치로 보기`**(GPS)를 넣었다.
- **읍면동·시군구·시도 경계**를 지도에 그린다. 시도만 원본이 3MB라
  `tools/build_boundaries.py`로 미리 단순화해 `data/sido.json`(367KB)에 넣어 뒀다.

        │          VWorld ── 서울 중계 ──▶ 좌표 ✅
        │          Anthropic ─ 직접 ────▶ 해석 ✅
        │
        ├─▶ [안전장치] 건수 0 이거나 절반 아래면 커밋 안 함
        │
        └─▶ 커밋 ──▶ deploy.yml ──▶ 사이트 배포 ✅


  ■ 손으로 돌리는 길 (그대로 남아 있다. 급할 때만)

  [담당자 PC — 한국]  run_daily.bat 더블클릭
    수집(EIASS 직접) → 커밋 → 푸시 ──▶ deploy.yml → 배포 ✅
```

- **수집은 사람이 한다.** 매일 아침 `tools\run_daily.bat` 더블클릭.
- **배포는 자동이다.** 푸시만 되면 `deploy.yml`이 알아서 올린다. 이쪽은 문제없다.
- **자동 수집이 실패해도 사이트는 안 죽는다.** 어제 자료로 정상 동작한다
  (화면이 날짜를 다시 판단하므로 기한 지난 사업이 새어 나가지 않는다).
- 실패하면 GitHub이 저장소 주인에게 메일을 보낸다. 하루 두 번 온다.
  귀찮으면 `collect.yml`의 `- cron:` 두 줄을 주석 처리한다.

## 5. 알려진 함정 (다 실제로 겪은 것)

| 함정 | 증상 | 대응 |
|---|---|---|
| **EIASS 접속이 간헐적으로 안 됨** | 어떤 날은 DNS 조회 실패, 어떤 날은 TCP 무응답 (**차단 아님**, §4) | `build_data.py`의 `SESSION`이 4·8·16초 쉬며 4번 재시도. 하루 두 번 실행 |
| **"연결이 되나"와 "실제로 되나"를 헷갈림** | 점검이 `curl https://api.vworld.kr/` 에 응답만 오면 "OK"라고 답했다. **정작 지오코딩은 하나도 안 되고 있었다.** VWorld 는 키를 거부할 때도 **HTTP 200** 에 `status=ERROR` 를 담아 준다 | 점검은 **실제로 쓰는 방식 그대로** 부른다. 상태 코드가 아니라 **본문의 `status` 를 읽는다** |
| **수집 알림의 `VWorld FAIL` 은 고장이 아니다** (2026-11-03 확인) | 수집 실행 화면 Annotations 에 `[통로] 서울 중계로 EIASS 연결 성공 … / VWorld FAIL` 이 **매번** 뜬다(최근 12번 모두, 성공한 수집에서도) | `collect.yml:105` 가 GitHub 서버(미국)에서 VWorld 로 **곧장** 붙어 보는데, VWorld 는 그 길에 원래 답하지 않는다. 실제 수집은 **서울 중계로** VWorld 를 써서 잘 된다(노선·좌표가 들어온다). **그대로 두기로 했다**(사용자 결정). VWorld 가 진짜 죽었는지는 `속 알맹이 점검` 의 좌표·노선 줄로 본다 |
| **실패를 조용히 삼킴** | 새 사업 좌표가 하나도 안 채워졌는데 **로그가 깨끗했고 수집도 '성공'으로 끝났다.** `geocode_address()` 가 '주소를 못 찾음'과 '거부당함'을 구분 없이 `(None,None)` 으로 넘겼다 | `NOT_FOUND` 가 아닌 응답은 `[지오코딩 거부] status=...` 로 남긴다. **'실패'가 아니라 '반쪽 성공'은 어떤 안전장치에도 안 걸린다** |
| **HTTP 헤더에 한글** | 중계가 오류 까닭을 한글로 헤더에 담았다가, **오류를 알리려다 그 자리에서 또 죽었다**(헤더 값은 라틴 문자만 된다) | 까닭은 **본문**에, 헤더에는 **짧은 아스키 코드**만 |
| **셸 heredoc 이 백슬래시를 먹음** | `collect.yml` 에 `tr -d '\r'` 을 넣었더니 **실제 CR 바이트**가 파일에 박혀 YAML 이 깨졌다. 줄 이음(`\`)도 사라졌다 | 셸 heredoc 으로 코드 파일을 쓰지 않는다. **편집 도구나 파이썬 파일**로 쓴다 |
| **셸에 한글을 박은 판정 스크립트** | 인코딩이 깨져 **8번 성공한 것이 8번 실패로 찍혔다.** 판정을 뒤집을 뻔했다 | 측정·판정 코드는 **파일로 빼서** 돌린다. 셸 한 줄로 판정하지 않는다 |
| **저장소와 배포본이 조용히 어긋남** | Supabase 대시보드는 **버전 관리가 없다.** `tools/relay/index.ts` 만 고치고 배포를 안 하면 옛 판이 계속 돈다(허용 목록을 늘렸는데 `403 not-allowed` 로 막힘) | 고쳤으면 **반드시 다시 배포**하고 `check.yml` 로 확인. 이제 **Supabase 커넥터로 AI 가 직접 배포·대조할 수 있다** |
| **한 번 실패를 "확인함"으로 단정** | 틀린 제약이 문서 3곳에 박혀 반년 갈 뻔했다 (§4) | 제약을 문서에 넣기 전에 **두세 번 재현**해 볼 것 |
| **목록 받다 끊기면 통째로 죽음** | 2026-08-06 수집 실행이 100초 만에 실패. 재시도 4번(≈78~100초)을 다 쓰고 예외가 그대로 터졌다 | `fetch_open_items` 를 try 로 감싸 **아무것도 저장하지 않고** 안내 후 중단. 반쪽 저장이 더 위험하다 |
| **반쪽 수집이 안전장치를 통과함** | 전략 43건만 받고 환경 16건을 놓치면 48→43건. 10% 감소라 `collect.yml` 의 "절반 이하면 중단"을 통과해 버린다 | 목록 실패 시 아예 저장하지 않는 것으로 막았다 |
| **소넷은 `max_tokens`를 생각+답변이 나눠 쓴다** | 모델만 소넷으로 바꾸고 `max_tokens=6000`을 그대로 두면 생각하다 자리를 다 써서 JSON이 잘린다 | 소넷으로 바꿀 때는 **16000으로 같이 올린다**. `b.type=="text"` 필터도 필수(생각 덩어리가 섞여 옴) |
| **Actions 로그는 저장소 주인만 본다** | 도와주는 사람이 실패 원인을 못 봐서 진단이 계속 막혔다 (`403 Must have admin rights`) | `::error::` / `::notice::` **주석**으로 내보내면 누구나 API로 읽는다. `collect.yml`·`check.yml`이 그렇게 한다 |
| **한 번 성공을 "된다"로 단정** | 3번 중 1번 성공을 보고 자동화를 켰다가 3번 연속 실패 | 접속이 안 될 땐 몇 분간 계속 안 된다. 재시도로 안 덮인다 (§4) |
| **시험용 `--limit`이 진짜 데이터를 덮어씀** | `--limit 3`으로 돌리면 48건이 6건으로 줄어 그대로 커밋됨 | `collect.yml`이 `limit` 있으면 커밋 안 함 + 건수 급감 시 중단 |
| **VWorld 키 앞뒤 공백** | 지도 타일은 나오는데 지오코더만 `INVALID_KEY` | 코드 3곳에서 `strip()`. 거부되면 길이부터 세어 본다 |
| **★ `assets/config.js` 에 키를 적어 두고 커밋** | 2026-08-07 실제 발생. 화면 확인하려고 키를 잠깐 넣었는데 그대로 커밋·푸시되어 **공개 저장소에 키가 남았다**(`514496a`). git 은 지운 뒤에도 옛 커밋에 값을 계속 가진다 | **키를 새로 발급받는 것 외에 되돌릴 방법이 없다.** 예방: 내 PC 에서 지도를 볼 땐 `config.js` 말고 **관리자 화면**에 넣는다(브라우저에만 저장됨). 커밋 전 `config.js` 가 `vworldKey: ""` 인지 항상 확인 |
| **시험용 임시 html 이 커밋에 섞임** | `_m_test.html`(화면 확인용 사본)이 `514496a` 에 같이 들어갔다 | `.gitignore` 에 `_*.html` 추가. 임시 파일은 **밑줄로 시작**하는 이름만 쓴다 |
| **`.bat` 줄바꿈이 LF** | 더블클릭해도 조용히 안 열림 | 반드시 CRLF. `.gitattributes`로 고정 |
| **배치 `ERRORLEVEL`** | 멀쩡한 실행이 "실패"로 끝남 | `echo` 뒤 말고 명령 직후 바로 확인 |
| **목록 표가 두 개 / 날짜순 아님** | 중복 수집·누락 | 사업번호로 중복 제거, 빈 페이지 5쪽까지 넘겨봄 |
| **AI 응답 잘림** | JSON 파싱 실패로 해석 통째 유실 | `max_tokens` 6000, 잘리면 `stop_reason` 로그 |
| **증분 수집이 옛 값을 붙잡음** | `미정`으로 한 번 저장되면 영영 `미정` | `needs_detail_refresh()` — 안 정해진 값 있으면 상세 재조회(PDF·AI는 건너뜀) |
| **브라우저가 옛 app.js를 붙잡음** | 배포는 됐는데 화면은 옛 코드 | 자산 주소에 `?v=커밋SHA`를 배포 때마다 자동으로 심음(`deploy.yml`) |
| **★ 커밋을 연달아 하면 배포가 죽는다** | 7분 간격으로 두 번 커밋 → 앞 배포가 **올리는 도중 잘림** → 뒤 배포가 10분 기다리다 `Timeout reached, aborting!` 으로 실패. **사이트는 옛 판 그대로**라 "고쳤는데 그대로네?"가 된다 (2026-08-06 겪음) | `deploy.yml` 의 `cancel-in-progress` 를 **false** 로. 올리는 중인 배포는 끝까지 두어야 한다 (GitHub 공식 Pages 워크플로도 false) |
| **배포 실패를 모르고 화면만 의심함** | 폰에서 안 바뀌길래 판정 규칙·브라우저를 의심했는데, 실제로는 배포가 실패해 파일이 안 올라가 있었다 | **먼저 파일이 살아 있는지 본다** — 브라우저에서 `.../alrimi/m.html` 을 직접 연다. 404면 배포 문제지 화면 문제가 아니다 |
| **격자 `1fr`이 상자보다 넓어짐** | 휴대폰에서 오른쪽이 잘려 보임(스크롤도 안 생김) | `minmax(0,1fr)` + `min-width:0` |
| **`hidden`이 안 먹힘** | 클래스 `display`가 브라우저 기본을 이김 | `[hidden]{display:none!important}` 리셋에 추가 |
| **일시·장소 순서로 짝지으면 틀림** | 기장군 사업: 일시·장소 순서가 다름 | 지역 이름으로 매칭, 안 되면 원문 통째로 표시 |
| **`file://`로 열기** | 표본 데이터로 대체됨 | 반드시 `python -m http.server 8000` |
| **EIASS 상세는 POST 전용** | 링크로 못 엶 | 숨은 폼 제출 (`openEiassSource`) |
| **윈도우 cp949 콘솔** | 한글 로그에서 죽음 | 파이썬은 `log()` 사용 |
| **시도가 16개** | 17개가 아님 | 광주+전남이 VWorld 최신 자료 기준 통합됨 |
