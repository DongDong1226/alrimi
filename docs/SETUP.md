# 배포 설정 — 한 번만 하면 되는 일

이 문서는 **처음 한 번** 따라 하는 설명서다. 다 하고 나면 매일 아침 9시에 저절로 돌아간다.
전부 합쳐 20분쯤 걸린다. 코드를 고칠 일은 없다. 버튼을 누르고 값을 붙여넣는 게 전부다.

## 0. 무슨 일이 일어나는 건가

먼저 그림부터. **"서버"를 만드는 게 아니다.**

```
  매일 아침 9시
       │
       ▼
  GitHub 서버가 잠깐 켜져서 파이썬을 한 번 돌린다
       │  ① EIASS에서 공람 중인 사업을 받아온다
       │  ② 요약문 PDF를 읽어 AI로 쉬운 말로 옮긴다
       │  ③ 결과를 data/projects.json 으로 저장소에 저장
       │  ④ 사이트를 다시 만들어 올린다  ← 이때만 VWorld 키를 끼워 넣는다
       ▼
  일 끝나면 GitHub 서버는 다시 꺼진다
       │
       ▼
  방문자가 https://dongdong1226.github.io/alrimi/ 에 들어오면
  ③에서 저장해 둔 파일을 그냥 읽어서 보여준다
```

**항상 켜져 있는 서버는 없다.** 미리 만들어 둔 파일을 보여주는 구조라서 필요가 없다.
"GitHub Actions"는 서버가 아니라 **정해진 시각에 스크립트를 한 번 돌려주는 알람시계**에 가깝다.

우리 사이트 주소는 이것이 된다:

```
https://dongdong1226.github.io/alrimi/
```

## 1단계 — VWorld 인증키를 새로 발급받는다 (5분)

### 왜 새로 받아야 하나

지금 `.env`에 있는 키는 **`http://localhost:8000` 으로 등록**돼 있다. 즉 내 컴퓨터에서만 쓸 수 있다.
배포된 사이트(`dongdong1226.github.io`)에서 그 키를 쓰면 VWorld가 거절해서 **지도가 안 뜬다.**

> **"도메인 제한"이라는 별도 항목은 없다.** 신청서의 **`서비스URL` 칸이 곧 그 역할**이다.
> 거기 적은 주소에서 온 요청만 그 키를 쓸 수 있다.

그래서 키가 **두 개** 필요하다:

| 키 | 서비스URL | 어디에 두나 | 공개되나 |
|---|---|---|---|
| **지금 있는 키** | `http://localhost:8000` | `.env` (내 컴퓨터) | 아니오 |
| **새로 받을 키** | `https://dongdong1226.github.io/alrimi/` | GitHub Secret | 페이지 소스에 보임 |

새 키가 페이지 소스에 보이는 건 **웹지도의 어쩔 수 없는 성질**이다. 지도 타일은 방문자
브라우저가 VWorld에서 직접 받아오기 때문에 키가 브라우저에 있어야 한다. 서버를 만들어도 똑같다.
서비스URL을 걸어 두면 남이 퍼가도 자기 사이트에서는 못 쓴다.

### 신청서 채우는 법

vworld.kr → 오픈API → 인증키 발급. 화면의 칸마다 이렇게 넣는다.

| 칸 | 넣을 값 |
|---|---|
| **서비스명** | `우리동네 개발사업 알리미` |
| **서비스분류** | 목록에서 가장 가까운 것을 고른다 (환경 / 공공행정 계열) |
| **서비스유형** | `웹사이트` (기본값 그대로) |
| **서비스URL** | `https://dongdong1226.github.io/alrimi/` ← **여기가 제일 중요하다. 오타 나면 지도가 안 뜬다** |
| **서비스설명** | 아래 예시 참고 |
| **활용API** | `2D 지도 API`, `WMTS/TMS API`, `2D데이터 API`, **`지오코더 API`** — **네 개 모두** |
| **사용기관** | 실제 소속에 맞게 고른다 |
| **활용사례공개** | 원하는 대로 |

서비스설명 예시:

```
- 개요 : 환경영향평가 정보지원시스템(EIASS)에 공개된 초안 공람 자료를
         주민이 사는 동네 기준으로 모아 보여주는 웹 서비스
- 서비스대상 : 개발사업 관련 지식이 없는 일반 주민
- 목적 : 주민이 공람 기간 안에 의견을 낼 수 있도록 안내
```

**활용API를 왜 네 개 고르나** (각각 쓰는 곳):

| API | 쓰는 곳 | 빠뜨리면 |
|---|---|---|
| 2D 지도 / WMTS·TMS | 지도 배경 그림(타일) | 지도가 회색으로 빔 |
| **지오코더** | "경기도 하남시 미사동" → 위경도 | **반경 필터와 거리가 전부 틀어진다** |
| 2D데이터 | 하천 사업의 하천 모양 | 하천 노선이 안 그려짐 |

> ⚠️ **체크한 API만 허용된다.** 하나라도 빠뜨리면 그 기능만 조용히 안 된다.
> 실제로 2026-08-01에 `지오코더 API`를 빠뜨려서 지도는 나오는데 주소 변환이 안 되는
> 일이 있었다. 증상은 `INVALID_KEY — 등록되지 않은 인증키입니다.`
>
> **빠뜨렸으면 새로 발급받을 필요 없다.** vworld.kr → 마이페이지 → 인증키 관리에서
> 해당 키의 활용API를 수정하면 된다.

발급받으면 키 문자열이 나온다. **아직 아무 데도 붙여넣지 말고 창을 열어 둔다.** 2단계에서 쓴다.

## 2단계 — GitHub에 키를 숨겨 둔다 (3분)

키를 코드 파일에 적으면 저장소가 공개라 그대로 남는다. 그래서 GitHub이 따로 마련한
**Secret(비밀값) 보관함**에 넣는다. 여기 넣은 값은 저장소에서 보이지 않고,
스크립트가 돌 때만 꺼내 쓴다.

### 가는 길

```
github.com/DongDong1226/alrimi
  → 맨 위 [Settings] 탭
  → 왼쪽 메뉴 아래쪽 [Secrets and variables]
  → [Actions]
```

### Secrets 탭에 2개 넣기

`[New repository secret]` 초록 버튼을 누르고 하나씩 넣는다. **Name은 대소문자까지 똑같이** 적어야 한다.

| Name | Secret (값) |
|---|---|
| `VWORLD_KEY` | 1단계에서 새로 받은 키 |
| `ANTHROPIC_API_KEY` | `.env` 파일에 있는 것과 같은 값 |

> ⚠️ **붙여넣을 때 앞뒤에 공백이나 줄바꿈이 딸려 들어가지 않게 한다.**
> 공백이 한 칸만 붙어도 VWorld 가 키를 거부하는데, **지도 타일은 멀쩡히 나오고
> 주소 변환만 안 되기 때문에** 원인을 찾기가 아주 어렵다 (2026-08-01 실제로 겪음).
> 지금은 코드가 알아서 걷어내지만, 애초에 깨끗하게 넣는 편이 좋다.
> 키만 정확히 드래그해서 복사하거나, 붙여넣은 뒤 맨 앞·맨 뒤를 눌러 확인한다.

> **ANTHROPIC_API_KEY는 브라우저로 절대 안 간다.** 파이썬이 GitHub 서버 안에서만 쓰고,
> 사이트에는 들어가지 않는다. VWorld 키와는 성격이 완전히 다르다.

### Variables 탭에 1개 넣기

같은 화면 위쪽에 **`Variables`** 탭이 있다. 거기로 옮겨서 `[New repository variable]`:

| Name | Value |
|---|---|
| `VWORLD_DOMAIN` | `https://dongdong1226.github.io/alrimi/` |

**1단계의 서비스URL과 글자 하나까지 똑같아야 한다.** 하천 모양을 가져올 때 이 값을
VWorld에 같이 보내는데, 등록한 주소와 다르면 `INCORRECT_KEY` 오류가 난다.

> Secrets와 Variables의 차이: Secret은 넣고 나면 다시 못 본다(가려진다).
> Variable은 비밀이 아닌 값이라 그냥 보인다. 주소는 비밀이 아니니 Variable에 넣는다.

## 3단계 — Pages를 켠다 (1분)

```
Settings → 왼쪽 메뉴 [Pages]
  → "Build and deployment" 아래 Source
  → [GitHub Actions] 로 바꾼다
```

기본값은 "Deploy from a branch"인데, 그러면 저장소에 있는 파일을 그대로 올린다.
그러면 **VWorld 키를 파일에 적어 커밋해야만** 지도가 나온다 — 공개 저장소라 그건 안 된다.

`GitHub Actions`로 바꾸면 **올리기 직전에만 키를 끼워 넣을 수 있다.**
그래서 키가 저장소 기록에는 남지 않는다.

## 4단계 — 손으로 한 번 돌려본다 (5분) ★ 제일 중요

자동으로 켜두기 전에, **되는지부터 확인**한다.

```
맨 위 [Actions] 탭
  → 왼쪽 목록에서 [EIASS 공람 자료 수집]
  → 오른쪽 [Run workflow ▾] 버튼
  → limit 칸에 3 입력
  → 초록 [Run workflow]
```

`limit 3`은 "유형별로 3건만 시험 삼아 받아라"라는 뜻이다. 전건(36건)을 돌리기 전에
연결이 되는지만 확인하는 것이다.

1~2분 뒤 목록에 노란 점 → 초록 체크로 바뀌면 성공이다. 눌러서 로그를 펼쳐 본다.

### 로그에서 확인할 것

**① EIASS 연결 — 이게 이번 설정의 최대 관문이다**

```
  [전략환경영향평가] 1페이지 (20건 중 공람중 10건, 누적 10건)
```

이런 줄이 보이면 통과다.

**여기서 막힐 수 있다.** 한국 정부 사이트는 해외 IP를 차단하는 경우가 있고,
GitHub 서버는 미국에 있다. 내 컴퓨터(한국)에서 되는 게 GitHub에서도 된다는 보장이 없다.
**이건 실제로 돌려보기 전에는 알 방법이 없다.**

막혔을 때 나오는 모습: `Timeout`, `403 Forbidden`, `Connection refused`

→ 막혔으면 **6단계**로 간다.

**② VWorld 하천 조회**

```
    선형/하천 사업: 하천 이름 2개, 노선 도형 1개
```

`INCORRECT_KEY`가 보이면 2단계의 `VWORLD_DOMAIN`이 1단계 서비스URL과 다른 것이다.

**③ AI 해석**

```
    환경영향분석 8/8개 항목 채움
```

`credit balance is too low`가 보이면 Anthropic 크레딧을 충전해야 한다.

**④ 배포**

수집 다음에 `사이트 배포`가 이어서 돈다. 끝나면 로그 맨 아래 사이트 주소가 나온다.
눌러서 들어가 본다. **지도가 보이고 사업 목록이 나오면 전부 성공이다.**

## 5단계 — 전건을 받고 자동 실행에 맡긴다

4단계가 다 통과했으면 이번엔 `limit`을 **비워 두고** 다시 `Run workflow`.
전국 36건을 다 받는다. 10분쯤 걸리고 비용은 1,300원 정도다.

이후로는 **손댈 게 없다.** 매일 아침 9시에 저절로 돌고,
이미 받아 둔 사업은 건너뛰므로 하루 2분·월 3,000원 안쪽이다.

## 6단계 — 수집도 GitHub이 알아서 한다 ★ 여기서 끝이다

**설정할 게 없다. `collect.yml`이 이미 켜져 있다.**

매일 한국시간 **09시와 13시**에 저절로 돌아 수집 → 커밋 → 배포까지 이어진다.
PC를 켜 둘 필요도, 작업 스케줄러를 등록할 필요도 없다.

```
  매일 09시·13시 (한국시간)
        │
        ▼
   collect.yml ──▶ EIASS 수집 (연결 안 되면 4·8·16초 쉬며 최대 4번 재시도)
        │              │
        │              ▼
        │         건수 확인: 0건이거나 절반 아래로 급감하면 → 커밋 안 하고 멈춤
        │              │
        │              ▼
        │         커밋 → 푸시
        ▼
   deploy.yml ──▶ 사이트 배포
```

> **13시 실행은 왜 있나?** EIASS 접속이 가끔 안 되기 때문이다(아래 참고).
> 09시에 성공했으면 이미 받아 둔 사업은 건너뛰므로 비용도 시간도 거의 안 든다.

### 잘 도는지 확인하는 법

저장소 → **Actions** 탭 → `EIASS 공람 자료 수집`. 초록불이면 정상이다.
**실패하면 GitHub이 저장소 주인에게 메일을 보낸다.** 따로 들여다볼 필요 없다.

### 가끔 실패해도 괜찮다

EIASS 접속이 **간헐적으로 불안정하다.** 어떤 날은 주소 조회가 안 되고, 어떤 날은
연결이 무응답이다. (예전에 "해외 IP 차단"이라고 적혀 있었는데 **사실이 아니었다** —
미국·독일·프랑스 등 해외 17곳에서 정상 접속되고, GitHub 서버에서도 0.23초에 붙는다.
자세한 경위는 `docs/HANDOFF.md` §4에 있다.)

그래서 이렇게 대비해 뒀다:

| 무엇 | 어떻게 |
|---|---|
| 연결이 안 될 때 | 4초·8초·16초 쉬며 **최대 4번 다시 시도**한다 |
| 그래도 안 될 때 | 13시에 **한 번 더** 시도한다 |
| 그날 끝내 실패하면 | 자료가 안 바뀔 뿐 **사이트는 어제 자료로 정상 동작**한다 |
| 수집이 반쪽만 됐을 때 | 건수가 절반 아래로 급감하면 **커밋하지 않고 멈춘다** |

**이틀 연속 실패할 때만** 들여다보면 된다.

### 급할 때 손으로 돌리기

기다리기 싫으면 두 가지 방법이 있다.

- **Actions 탭에서**: `EIASS 공람 자료 수집` → `Run workflow`
- **내 PC에서**: `C:\dev\EIASS\tools\run_daily.bat` 더블클릭
  (`[완료] 자료를 올렸습니다.` 가 나오면 성공. 실패하면 `data\build_log.txt` 확인)

> ⚠️ Actions에서 돌릴 때 **`limit`은 시험용이다.** 값을 넣으면 일부만 수집하므로
> **일부러 커밋하지 않게** 해 뒀다. 진짜 갱신을 원하면 비워 두고 돌린다.

### EIASS에 닿는지만 확인하고 싶을 때

Actions 탭 → `EIASS 연결 확인 (시험용)` → `Run workflow`.
데이터를 건드리지 않고 30초 만에 "닿는다/안 닿는다"만 알려 준다.

## 문제가 생기면

| 증상 | 원인 | 할 일 |
|---|---|---|
| 사이트에 지도 자리가 비고 안내 문구만 | `VWORLD_KEY` Secret이 없거나 이름 오타 | 2단계 다시 확인 (`VWORLD_KEY`, 대문자) |
| 지도 타일이 회색 | 서비스URL이 실제 주소와 다름 | 1단계 서비스URL을 `https://dongdong1226.github.io/alrimi/` 로 수정 |
| **지도는 나오는데 반경 안 사업이 0건이고 거리가 이상함** | **키에 `지오코더 API` 가 빠졌다** | vworld.kr 마이페이지 → 인증키 관리 → 활용API에 `지오코더 API` 추가 |
| 브라우저 콘솔에 `INVALID_KEY` | 그 API가 키에 등록되지 않음 | 위와 같음 |
| 로그에 `INCORRECT_KEY` | `VWORLD_DOMAIN` Variable이 서비스URL과 다름 | 두 값을 글자 하나까지 똑같이 |
| 더블클릭했는데 창이 깜빡이고 닫힘 | `.bat` 줄바꿈이 LF | CRLF로 저장해야 한다 (`.gitattributes`가 고정해 둠) |
| 사업이 안 보이고 표본 안내 띠가 뜸 | `data/projects.json`이 안 올라감 | Actions 로그에서 수집이 성공했는지 확인 |
| 로그에 `credit balance is too low` | Anthropic 크레딧 소진 | console.anthropic.com에서 충전 |
| Actions 탭에 아무것도 없음 | 워크플로 파일이 아직 푸시 안 됨 | `.github/` 폴더를 커밋·푸시 |
| 수집은 됐는데 배포가 안 됨 | Pages Source가 아직 브랜치 방식 | 3단계 다시 |
